# Live Activity spike and local build, before the paid account

> **For agentic workers:** execute task by task. Tasks marked **now** need no Apple Developer Program membership;
> tasks marked **account** wait on it (push). Only one Simulator-using agent runs at a time. Live Activity sign-off is
> on a physical device (foundation Known limits); Simulator runs are for development only.

**Status:** proposed 2026-11-11. Tasks 1 and 2 (spikes) are done (branch `spike/iap-live-activity`, 「Spike results」
below); Task 3 needs the owner's iPhone; 274–278 answered A (2026-11-12); Task 4 (the views) built 2026-11-12
(「Views as built」 below); Task 5 (app wiring) built 2026-11-12 (「App wiring as built」 below); Tasks 6–9 wait on the
account.

**Goal:** While a helper is on the way (bounty `en_route`) or a ride is gathering (集合), the Lock Screen and the
Dynamic Island show one sentence and a progress line, started and updated by the app. Before the account exists this
is built and tried with local ActivityKit calls only; push updates and push-to-start come with the account.

**Architecture:** A widget extension target generated by a config plugin (the one exception to 「native code lives in
the kit」, F12); its SwiftUI views and the shared `ActivityAttributes` type live under `modules/tapiro-kit`; the kit
facade exposes `start`, `update`, `end` and `list` to `src/lib/live-activity`; bounty and carpool screens hand it
plain state through `src/lib` (features do not import each other). The push half adds ActivityKit push tokens to
`push_tokens` and a `liveactivity` sender to `notify`.

**Tech stack:** Expo SDK 58 config plugins, Swift (ActivityKit, WidgetKit, SwiftUI; iOS 26.0+), TypeScript,
`bun test`.

**Spec:** `docs/specs/2026-10-11-foundation-design.md` (Decision 「Live Activity target」; Behaviour 「Notifications and
Live Activities」; Craft detail 1; Open points; Implementation order 9; Known limits).
`docs/specs/2026-10-31-realtime-push-design.md` (174 A). `docs/specs/2026-11-02-carpool-design.md` (32, the four
phases). Plan `docs/plans/2026-11-03-realtime-push.md` (step 3 waits on the account). Story map:
`home.live-activity.top-item`, `home.live-activity.in-app`.

## Gaps found while preparing

1. **Simulator support is unverified.** Apple's article does not say whether Live Activities render on the
   Simulator; the foundation spec already makes device the sign-off. Task 1 measures it.
2. **Local-only updates go stale.** Without push, an update needs the app running: a helper's ETA change or the ride
   moving to 上车 while the phone is locked reaches the Live Activity only when Tapiro runs. The data-integrity rule
   (「Never show stale data as live」) needs `staleDate` and a stale look. Asked as 278.
3. **Lock Screen privacy.** A Live Activity is readable on a locked phone by anyone holding it: names, places and
   times. Ride starts of kind `home` point at where someone lives (256 gap). Asked as 274.
4. **The shared type.** The app (through the kit) and the extension both compile the `ActivityAttributes` type;
   keeping one copy in the kit while the extension is a separate target is the reason to prefer our own plugin.
5. **A device with a Dynamic Island.** The in-app island spike needs the owner's iPhone (Developer Mode, free
   provisioning). Owner action, not a purchase.
6. **The look is not drawn.** CraftPick drew the craft detail, not the four presentations (Lock Screen, compact,
   minimal, expanded) with Tapiro data. Asked as 276, drawn on the canvas first.

## Rulings (agent, for veto)

- **L1 Plugin: our own `withLiveActivity`.** ★ Reason: F12 keeps shared code in the kit, and only our plugin can
  compile one attributes file into both the kit and the extension. Read `@bacons/apple-targets`' widget target code as
  the reference. Fallback: `@bacons/apple-targets` with the attributes file in `targets/_shared` if Task 2 exceeds its
  time box. `expo-widgets` is not used: the mascot art and the expanded layout need SwiftUI beyond Expo UI, and its push
  payload format is internal.
- **L2 No app group, no push entitlement** in the now half; `withoutPushEntitlement` stays until the account.
- **L3 Data in ContentState only:** short strings and numbers, under 1 KB, never a phone number, payee detail or
  exact address; the extension makes no network call.
- **L4 `staleDate`** = the next expected change (ETA plus 5 minutes, or departure); stale content shows the system
  stale treatment with 「可能不是最新」, as in 172 B.
- **L5 Facade** follows the kit rules: typed result codes from Swift (`unsupported`, `disabled`, `tooMany`, `failed`),
  activity IDs as strings, an event for `activityStateUpdates`, removed on unmount.

### Spike B: plugin shape

- `plugins/withLiveActivity.js` adds the `TapiroLiveActivity` app extension (`app.tapiro.LiveActivity`, widgetkit
  extension point, iOS 26.0, iPhone only, automatic signing with the app's team when one is set), embeds it in
  「Embed Foundation Extensions」 with one target dependency, writes its `Info.plist`, and sets
  `NSSupportsLiveActivities` on the app. No app group, no push entitlement (L2).
- One copy of each Swift file: `modules/tapiro-kit/ios/LiveActivity/TapiroActivityAttributes.swift` is compiled by the
  kit pod (its source glob) and, by path reference, by the extension; the extension's views live in
  `modules/tapiro-kit/widget/` (outside the pod glob). ActivityKit matched the two copies (the activity rendered).
- `expo prebuild --clean` with the flag twice: the project differs only in the generated object ids; `Info.plist`
  files are identical. Signed ad hoc for the Simulator; signing was never disabled.
- Gate: the plugin does nothing unless prebuild runs with `TAPIRO_LIVE_ACTIVITY=1`, so verify and release builds carry
  no extension and no `NSSupportsLiveActivities` until 274–278 are answered (checked: a plain prebuild has neither).
  The kit's `LiveActivity` facade (`start`, `update`, `end`, `list`, typed codes `disabled`, `unsupported`, `tooMany`,
  `tooLarge`, `unentitled`, `failed`) is compiled always and called only from the dev-only scene.

## App wiring as built (Task 5, 2026-11-12)

275 A: the activity starts by itself while Tapiro is open, as a bounty enters `en_route` or a ride enters 集合; the
system's per-app switch turns it off. Read the 275 board (「锁屏实时活动 · 写什么、什么时候开始」) before building: it
draws no Tapiro control, only the system's 「允许来自 Tapiro 的实时活动吗？」 on the Lock Screen the first time.

- Server: `public.live_activity_subjects()` (migration `20261112000400`) returns only what the Lock Screen shows
  (274 A): for the poster, the helper's display name, the place label, the task, the start and ETA times, or the 完成
  time; for ride crew, the start's short name and whether it is of kind `home`, the 集合 and departure times, arrived
  and total, or the departure time and how many boarded. A final step stays listed for its 15 minutes (277 A).
  pgTAP: `supabase/tests/live_activity_subjects.test.sql`.
- Client, `src/lib/live-activity`: `parse.ts` reads the rows; `plan.ts` decides start, update and end from the running
  activities (kit `list`), the rows and the record of items already started; `controller.ts` runs one plan at a time;
  `instance.ts` reads on sign-in, on return to the foreground, on the `bounty.started`, `bounty.eta_changed`,
  `bounty.completed`, `bounty.cancelled` and `ride.*` signals, and redraws once a minute while Tapiro is open.
  `useLiveActivities` is mounted in the tabs layout; its subscriptions are removed on unmount. Signals that arrive
  together cause one read. Sign out and account deletion end Tapiro's activities at once and pause the wiring until
  the next account.
- Kit: `LiveActivity.enabled()` (`areActivitiesEnabled`), and `list()` returns each activity's `link` and an explicit
  state (`active`, `stale`, `ended`, `dismissed`, `pending`).
- After a relaunch nothing is held in memory: every plan starts from `list()`, so a running activity is found and
  updated, or ended with what is left of its 15 minutes, never started twice.
- Measured in #120: `end()` takes the activity out of the Dynamic Island at once; only the Lock Screen keeps the final
  step for the 15 minutes. So V5 (the checkmark in the compact island) never shows. W1 below.
- The Simulator run is in the PR: 阿明 taps 出发了 (`start_bounty` through the local stack) while 小林 has Tapiro open,
  and 小林's Lock Screen shows the activity.
