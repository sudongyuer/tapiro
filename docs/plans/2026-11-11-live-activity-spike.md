# Live Activity spike and local build, before the paid account

> **For agentic workers:** execute task by task. Tasks marked **now** need no Apple Developer Program membership;
> tasks marked **account** wait on it (push). Only one Simulator-using agent runs at a time. Live Activity sign-off is
> on a physical device (foundation Known limits); Simulator runs are for development only.

**Status:** proposed 2026-11-11. Tasks 1 and 2 (spikes) can start now; Task 4 (the look) waits on questions 274–278.

**Goal:** While a helper is on the way (bounty `en_route`) or a ride is gathering (集合), the Lock Screen and the
Dynamic Island show one sentence and a progress line, started and updated by the app. Before the account exists this
is built and tried with local ActivityKit calls only; push updates and push-to-start come with the account.

**Architecture:** A widget extension target generated by a config plugin (the one exception to 「native code lives in
the kit」, F12); its SwiftUI views and the shared `ActivityAttributes` type live under `modules/tapiro-kit`; the kit
facade exposes `start`, `update`, `end` and `list` to `src/lib/live-activity`; bounty and carpool screens hand it
plain state through `src/lib` (features do not import each other). The push half adds ActivityKit push tokens to
`push_tokens` and a `liveactivity` sender to `notify`.

**Tech stack:** Expo SDK 58 config plugins, Swift (ActivityKit, WidgetKit, SwiftUI; iOS 26.0+), TypeScript,
`bun test`.

**Spec:** `docs/specs/2026-10-11-foundation-design.md` (Decision 「Live Activity target」; Behaviour 「Notifications and
Live Activities」; Craft detail 1; Open points; Implementation order 9; Known limits).
`docs/specs/2026-10-31-realtime-push-design.md` (174 A). `docs/specs/2026-11-02-carpool-design.md` (32, the four
phases). Plan `docs/plans/2026-11-03-realtime-push.md` (step 3 waits on the account). Story map:
`home.live-activity.top-item`, `home.live-activity.in-app`.

## Decided (do not re-ask)

  kit (F12, AGENTS.md).
- Live Activities for bounty `en_route` and ride 集合 (174 A). The foundation's wider list (「ride countdown, helper on
  the way, payment due」) is narrowed by 174 A; payment due has no Live Activity.
- One sentence and a progress line, glance-ranked, the top in-progress item (foundation, craft detail 1; carpool 32

## Gaps found while preparing

1. **Simulator support is unverified.** Apple's article does not say whether Live Activities render on the
   Simulator; the foundation spec already makes device the sign-off. Task 1 measures it.
2. **Local-only updates go stale.** Without push, an update needs the app running: a helper's ETA change or the ride
   moving to 上车 while the phone is locked reaches the Live Activity only when Tapiro runs. The data-integrity rule
   (「Never show stale data as live」) needs `staleDate` and a stale look. Asked as 278.
3. **Lock Screen privacy.** A Live Activity is readable on a locked phone by anyone holding it: names, places and
   times. Ride starts of kind `home` point at where someone lives (256 gap). Asked as 274.
4. **The shared type.** The app (through the kit) and the extension both compile the `ActivityAttributes` type;
   keeping one copy in the kit while the extension is a separate target is the reason to prefer our own plugin.
5. **A device with a Dynamic Island.** The in-app island spike needs the owner's iPhone (Developer Mode, free
   provisioning). Owner action, not a purchase.
6. **The look is not drawn.** CraftPick drew the craft detail, not the four presentations (Lock Screen, compact,
   minimal, expanded) with Tapiro data. Asked as 276, drawn on the canvas first.

## Rulings (agent, for veto)

- **L1 Plugin: our own `withLiveActivity`.** ★ Reason: F12 keeps shared code in the kit, and only our plugin can
  compile one attributes file into both the kit and the extension. Read `@bacons/apple-targets`' widget target code as
  the reference. Fallback: `@bacons/apple-targets` with the attributes file in `targets/_shared` if Task 2 exceeds its
  time box. `expo-widgets` is not used: the mascot art and the expanded layout need SwiftUI beyond Expo UI, and its push
  payload format is internal.
- **L2 No app group, no push entitlement** in the now half; `withoutPushEntitlement` stays until the account.
- **L3 Data in ContentState only:** short strings and numbers, under 1 KB, never a phone number, payee detail or
  exact address; the extension makes no network call.
- **L4 `staleDate`** = the next expected change (ETA plus 5 minutes, or departure); stale content shows the system
  stale treatment with 「可能不是最新」, as in 172 B.
- **L5 Facade** follows the kit rules: typed result codes from Swift (`unsupported`, `disabled`, `tooMany`, `failed`),
  activity IDs as strings, an event for `activityStateUpdates`, removed on unmount.

## Tasks

### Now (no account)

1. **Spike A, render (now).** In the kit, a throwaway `ActivityAttributes` and a minimal Lock Screen and island view;
   our plugin generates the extension; build signed with the existing team (never disable signing). On the iOS 27.2
   Simulator: start, update, end from a Debug scene; record whether the Lock Screen and the island render, and
   screenshots. Previews of all four presentations in Xcode. Time box 3 h.
2. **Spike B, plugin shape (now).** `plugins/withLiveActivity.js`: target, Info.plist (`NSSupportsLiveActivities` on
   the app), deployment target 26.0, the shared file in both targets, `pod install` after prebuild; survives
   `bunx expo prebuild --clean --platform ios` twice with no diff. Decide L1; time box 4 h.
3. **Spike C, device (now, needs the owner's phone).** `home.live-activity.in-app`: does the island show while Tapiro
   is in the foreground; does an update from the background (app suspended) arrive; record on device.
4. **Views (now, after 274, 276, 277 are drawn and answered).** Lock Screen, compact, minimal, expanded for bounty
   `en_route` and ride 集合 / 上车 / 到了 in zh-Hans, en, ms (longest copy), light and dark, Dynamic Type at the default
   size; VoiceOver labels.
5. **App wiring (now, after 275 and 278).** `src/lib/live-activity`: start on the 275 trigger, update on the realtime
   signals already received in the foreground (`bounty.eta_changed`, ride status), end on completion, cancel or sign
   out; recover with `list` after relaunch. Unit tests on the selection of the top item and on start / end rules;
   a Debug scene for each state.

### Account (waits on the paid Apple Developer Program)

6. **Push tokens.** Remove `withoutPushEntitlement`; request with `pushType: .token`; send `pushTokenUpdates` to the
   server (a `live_activity_tokens` table or a kind on `push_tokens`), invalidate replaced tokens.
7. **Sender.** `notify` gains a `liveactivity` path (`apns-push-type: liveactivity`, topic
   `app.tapiro.push-type.liveactivity`, `content-state` matching the attributes); check first whether Expo's push
   service sends this type, else a direct APNs sender with a `.p8` key stored as a Supabase secret.
8. **Push-to-start** (iOS 17.2+), if 275 chooses it, and `NSSupportsLiveActivitiesFrequentUpdates` only if updates are
   measured to need it.
9. **Device run and records.** `home.live-activity.top-item` on a phone over TestFlight; realtime spec step 3 and
   foundation step 9 Implementation Records.

## Open questions (274–278)

Context for all: foundation step 9, Live Activity for bounty `en_route` and ride 集合 (174 A, decided). Each question is
drawn as Tapiro screens on the canvas before it is asked (AGENTS.md).

274. **What a locked phone shows** (anyone holding the phone can read it).
     - A. ★ The other person's display name and the place's short name (「小林 · 约 6 分钟到 图书馆」); a ride start of kind
       `home` shows 「出发点」 instead of its name.
     - B. Roles only (「帮手约 6 分钟到」), no names or places.
     - C. Names and places, with a switch in 我的 to hide them on the Lock Screen.
275. **When it starts.**
     - A. ★ Automatically when the app is open as the item enters `en_route` or 集合; turned off with the system's
       per-app switch.
     - B. Only after a tap on 「在锁屏显示」 on the status or meet-up screen.
     - C. Automatically, plus a Tapiro setting in 我的 to turn it off.
276. **The look** (Lock Screen, compact, minimal, expanded).
     - A. ★ 小貘's head leading, the minutes trailing in the island; the Lock Screen shows the sentence over a progress
       line, the mascot at the left.
     - B. The item's sticker category icon in place of 小貘, same layout.
     - C. Text and progress only, no artwork.
277. **When it ends.**
     - A. ★ On arrival or departure it shows the final phase (「到了」) and leaves after 15 minutes; on cancel it leaves
       at once.
     - B. It leaves at once in every case.
     - C. It stays as long as the system allows (up to 4 h on the Lock Screen).
278. **Before push exists** (updates arrive only while Tapiro runs; a locked phone can show an old ETA).
     - A. ★ Build and try it locally, ship it only with push.
     - B. Ship the local version to TestFlight with `staleDate` and the stale look (L4).
     - C. Ship the local version only for ride 集合, where the meet-up screen is usually open.
