# Retro: pgTAP, Deno and stack tests in CI

A `supabase` job in `ci.yml` starts a local stack (CLI 2.122.1, Studio, imgproxy, logflare, vector, supavisor, mail
and postgres-meta left out) and runs `supabase test db`, `bun run test:deno`, then `bun run test:stack` against
`supabase functions serve` with the fake AI provider.

- **Runs on every PR, not only when `supabase/**` changes.** It took about 1 min 55 s, in parallel with `check` (about
  1 min 55 s), so it adds no wall-clock time. A path filter would miss `src/**/*.integration.ts` and `src/lib/drafts`,
  which `test:stack` covers. Stack start is about 75 s of it; image caching was not added because pulls are the only
  cost and the job does not lengthen CI.
- **Order makes it deterministic.** pgTAP runs first on the fresh database; `test:stack` leaves rows that break absolute
  counts such as `live_push` 35 (retro 2026-11-09), so it runs last and nothing reads the database after it.
- **Check failed (stale-stack-test).** The first CI run found two `paymentService.integration.ts` assertions broken on
  main: since #26 the payer gets a sticker too, and since #53 `mark_payment_paid` compares `expected_minor` with the
  payment's own amount, not the converted one. Nobody had run the whole `test:stack` since. Fixed the tests; the
  guarantee is now this CI job (code > rule).
- **Proof it fails.** A temporary commit changed `money.test.sql` test 2 to expect `closed`; the job failed on
  `Failed test 2: "¥800 is accepted"` (run 42748988898), then a revert commit restored it.
- AGENTS.md "Pace" no longer says "pgTAP when SQL changed"; CI runs it on every PR. No local stack or Simulator was used.
