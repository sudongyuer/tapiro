# Retro: accessibility checks

## Core (mandatory)

| Dimension | Measure               | This step                                                                                       |
| --------- | --------------------- | ----------------------------------------------------------------------------------------------- |
| Quality   | Escaped defects       | 0                                                                                               |
| Quality   | Skipped verifications | None; the tour ran in zh-Hans, en and ms at Large and once at AX5                               |
| Speed     | Wasted time           | ~40 min: a 40-case audit run per locale was planned before a one-case tour existed (see below) |
| Autonomy  | Interventions         | 0                                                                                               |

## Findings

- The first audit plan ran 40 ordinary cases per locale and again at AX5. At a load average of 60–120 that was about
  45 min a locale, and at AX5 every case whose assertions assume the Large layout would fail, reboot its Simulator and
  retry. One case that relaunches into each Debug scene and only captures (`a11y_screens`) covers the same screens in a
  few minutes and never fails on layout; the audit runs moved to it.
- `-UIPreferredContentSizeCategoryName` as a launch argument left the app at Large (the scene-based app reads the
  window scene's traits). `simctl ui <udid> content_size` works; the runner now sets it on every run, so a large-text
  run cannot leak into the next case.
- iOS 26 floating sheets scale their content (386 / 402): 44 pt buttons in the 问小貘 sheet reported 42.2 pt. The check
  undoes that scale rather than allow-listing each button.
- A text-overlap check on the accessibility tree was tried and dropped: sheets keep the screen behind them in the tree
  and the home cards overlap by design, so nearly every report was noise. Large-text clipping is judged from the AX5
  screenshots instead.
- AXe reports no traits, so a selected or disabled state is visible only through `enabled` and values; selected
  traits stay a device check (`docs/walkthroughs/2026-11-18-accessibility.md`).
