## Findings

- The probe that moved things logged the native side: `sizeThatFits` with the picker's own fitting size and date.
  It showed in one run that the picker reports the width of its previous text, which neither the AX widths nor the
  previous agent's patches could show. The first two kit builds changed the sizing before logging it; log first, then
  change. Tag `guessed-cause` (second time after `2026-11-19-bp13-chat-12h`).
- The case was calendar-dependent: it failed only on days whose tomorrow writes wider. `-uiVerifyToday` makes the
  day a case input like `LOCAL_HOURS` makes the hour; the old form then failed on both attempts, so the proof no
  longer waits for the calendar. Tag `date-dependent-case` (the 2026-10-31 bounty post redo lost ~30 min the same way).
- The first matrix run failed every run at 「the calendar did not open」: the kit row's identifier covers the title,
  and the case tapped the row's left edge (+40 pt), which had been the picker's date button. A case that taps by
  offset from an identifier's frame breaks when the identified element changes shape; it now taps the picker's own
  element. One run of the changed case in zh-Hans light before the matrix would have caught it. Tag `offset-tap`.
- Matrix (2 hour cycles × zh-Hans/en/ms × light/dark, 24-hour through a scratch copy of the case without
  `-AppleICUForce12HourTime`): 10 passed, 2 flaky whose first attempts passed the script and failed only on
  「video missing」 (en and ms light, the first runs on freshly booted Simulators; it also hit one zh-Hans run earlier).
  Not chased here. Tag `video-missing`.
- Kept: the probe ran the case's whole path (明天 → 时间段 → 截止 → 时间段) and ran in light and dark before any fix,
  as the previous retro asked (`one-probe-run`).
