# UI verification

Offline, deterministic UI checks on the iOS Simulator. A verify build (`EXPO_PUBLIC_UI_VERIFY=1`,
Release) runs without network or login; each case drives the real UI with AXe, asserts on the
accessibility tree, and captures screenshots and video in light and dark.

```bash
bun run verify:build          # prebuild if needed, Release build into .verify/DerivedData
bun run verify:ui             # all cases, light + dark → .verify/ui/<locale>/<appearance>/<case>/
bun run verify:smoke          # app_launches, sign_in_fixture, shell_tabs, home_one_card; zh-Hans light
bun run verify:ui --affected  # cases whose DEPS meet the diff against main; zh-Hans light
bun run verify:ui --affected --base main --dark --locales   # also dark, also en and each case's LOCALES
bun run verify:full           # the full matrix: every case, light + dark, zh-Hans + en + every declared locale
bun run verify:ui design_tokens --appearance dark   # named cases run zh-Hans; add --locales or --locale en
bun run verify:clean
```

The runner owns three named Simulators, `Tapiro Verify`, `Tapiro Verify 2` and `Tapiro Verify 3` (iPhone 17 Pro,
newest iOS runtime that offers it, skipping device-specific ones), creates each once if missing, and hands the runs to them from one queue; `--workers N` sets how many
it uses, and `--udid` runs on one given Simulator. Before booting more than one it checks that the disk holding the
checkout has at least 15 GB free and otherwise runs on `Tapiro Verify` alone, printing why (`pool.py`,
`python3 -m unittest test_pool`). The extra Simulators shut down when the run ends. The breaker below counts each
Simulator's runs on their own. Never create Simulators or pass another DerivedData path yourself.
`--affected` collects `git diff --name-only <base>...HEAD`, uncommitted changes and untracked files, and
picks each case whose `DEPS` prefixes (or its own file) match one, printing why. A change to shared code
(`affected.SHARED`: `src/ui/`, `src/lib/`, the root layout and index route, the Debug scenes (`src/debug/`, `src/app/debug/`), `modules/`, `plugins/`, `assets/`,
`app.json`, `package.json`, `bun.lock`, `tsconfig.json`, the runner, driver, selector, breaker, heal, latency, recording, records and Swift tool helpers, build script and string export)
picks every case; a case without `DEPS` always runs. Smoke and affected run zh-Hans light unless `--dark` or
`--locales` is given; the PR gate is smoke plus affected, and the full matrix runs when the machine is idle and
before TestFlight. `python3 -m unittest test_affected test_breaker test_pool test_heal test_strings test_driver test_runtime test_keyboard test_ride test_zone` in `verification/ui` covers the
selection (and checks that every case declares `DEPS` that match real paths, and that `DEPS`, `SCENE`, `LOCALES`,
`ARGS`, `BUDGET`, `TIME_ZONE` and `LOCAL_HOURS` are plain literals the runner reads without running the case); CI runs it. `ui.type` sends ASCII
only; paste other text with `bounty.paste_into`, or seed it through a launch argument such as `-uiVerifyApplyNote`.
`keys.py` types it. Lower-case letters, digits and spaces go as paced HID keys: an unpaced space from `axe type`
repeated, and the keyboard turned the double space into 「. 」 (「see you.      at the lobby」). On iOS 27.2 the number, decimal and phone pads drop AXe's HID keys (6 of 6, also after waiting), so digits
go to the on-screen pad keys, and `ui.backspace` to its delete key, whenever the keyboard lists no Return key.
A pad has no Return key, and the forms that hold one (and the place search results) dismiss the keyboard as soon as
they scroll, so `bounty.dismiss_keyboard(ui, container)` makes a short upward held drag on the form, as a person would;
a downward drag at the top of a sheet's form pulls the sheet closed instead (seen once in `bounty_post_optional`).
`ride.form_scroll_to` uses held drags too: an upward `axe swipe` from the top of the ride form's band did not scroll it
in en and ms (`ride_create_worst`, 10 of 10 swipes on 2026-11-10).
`bounty.end_editing` taps the keyboard's own Return (the key is in the accessibility tree with the identifier `Return`) and waits for it to go: on iOS 27.2 `axe key 40` leaves the field focused, 3 of 3 measured, while typed keys land, and a tap meant for a field under the keyboard then types a letter.
`profile.intrinsic_width` measures footnote text at Large with `textwidth.swift`, spawned the same way as the pasteboard tool, because AX reports neither truncation nor the rendered string: `assert_tier_whole` compares it with the text's frame.
`paste_into` writes the device pasteboard with `pasteboard.swift`, a UIKit tool run through `simctl spawn`, because
`simctl pbcopy` writes nothing on Xcode 27.2, and pastes from the edit menu (粘贴 / Paste / Tampal): an AXe ⌘V is not a
user-authenticated paste, so iOS asks for permission and the field stays empty.
Every time it prepares a Simulator (the owned ones, `--udid`, and after a stall), the runner writes the keyboard
settings with `simctl spawn <udid> defaults write` (`keyboard_commands` in `run.py`, `python3 -m unittest
test_keyboard`): global `AppleKeyboards` is US English plus emoji, `com.apple.keyboard.preferences` makes US English
current (`KeyboardsCurrentAndNext`, `KeyboardLastUsed`) and turns off `KeyboardPrediction` and
`KeyboardAutocorrection`. A new Simulator has no `AppleKeyboards`, so the app derives its keyboards from
`-AppleLanguages (zh-Hans)` and gets Pinyin, which turns typed ASCII into candidates; on the English keyboard,
prediction and autocorrection rewrite words (`klia` became `Kline`). The settings apply to the next app launch without
a reboot; `simctl erase` drops them, and the next run writes them again. Simulators run headless, so there is no
hardware keyboard: the software keyboard shows, and AXe's typed keys are not autocapitalised, so type text in the case
it should read (`Parcel`, not `parcel`).
Cases launch in `zh-Hans` (`-AppleLanguages`). The language order is zh-Hans > en > ms:
a PR run uses zh-Hans, a milestone run (`--locales`, and the full matrix) adds `en` for every case, and `ms` exists
only to catch truncation of the longest copy, so a case that shows long copy declares
`LOCALES = ['zh-Hans', 'ms']` and runs Malay at milestones. A case never needs to declare `en`.

App copy is never typed into a case. `run.py` runs `scripts/export-ui-strings.ts` once per invocation, which writes
every locale's strings (the `src/lib/i18n/locales` objects flattened by dotted key, the native permission strings
under `native.ios.*`, and `languages.<code>` for the picker names) to `.verify/ui-strings.json`. A case asserts copy
with `ui.t('pay.sheet.payTo', name='阿杰')` (i18next `{{name}}` interpolation, locale of the run); `ui.t_in(locale, key)` reads
another locale, `ui.tagged(key, 'terms')` returns the text inside a `<terms>` tag, `ui.pattern(key, amount=r'\d+')` builds a
regex from a string with placeholders, and `ui.other_locale()` gives a different language to switch to. A missing key raises,
so a renamed string fails the case instead of falling back. Fixture data (names such as 小林, task titles, amounts) stays
literal in the case. `ARGS = [...]` adds

Before each launch the runner deletes every record key the app writes in verify mode (`records.py`, `RECORD_KEYS`; `test_records` fails when the app gains a key the list misses), because the app's reset at launch reaches the plist seconds later and a case reading early saw the previous launch's calls (`chat-calls-stale`).

Live updates and push (`src/lib/live/`, `src/lib/push/`): `-uiVerifyLive <steps>` replaces the Realtime channel with an emitter. The channel joins at once when the signed-in tabs mount, and each comma-separated step `<ms>:<kind>:<id>` sends that signal, `<ms>:drop` drops the channel and `<ms>:back` joins it again (which refetches every live screen), all timed from that first join and played once; a step is a plist token, so no spaces. The verify build records timed events with `src/lib/verifyRecord.ts` as `{run, entries: [{label, at}]}` (`at` in ms since launch, `run` the launch argument `-uiVerifyLiveRun <id>`): each delivered step (`<kind>:<id>`, `drop`, `back`) in `uiVerifyLiveSteps`, each applicant load that starts in `uiVerifyApplicantLoads`, and each live bounty load that starts in `uiVerifyBountyLiveLoads`. The preferences file can lag by seconds and still hold the last launch, so a case relaunches with a fresh id and reads the records through `verification/ui/live.py` (`new_run`, `entries`, `step_at`, `starts`), which ignore entries of another run. The 「可能不是最新」 line shows 3 s after a drop. `-uiVerifyBountyLiveNext <rows>` makes the fixture live bounties answer those rows from the second load on, keeping each first-load row's bounty id, so a signal visibly changes the same home card. `-uiVerifyNoticeTap <kind>:<id>` is a notification tap the app reads once as a cold start (`getLastNotificationResponse` is replaced at that boundary; `xcrun simctl push` cannot tap a banner). The verify push registration uses the token `ExponentPushToken[uiVerify]` and records every `register_push_token` (also on a language change) and `unregister_push_token` call as a JSON array in the defaults key `uiVerifyPushCalls`, cleared at launch; `-uiVerifyNotifications provisional|allowed|denied|undetermined` sets the fixture permission (default `allowed`).

The signals are 20 s apart because one `axe describe-ui` took up to 7 s at a load average of 64.
A pull to refresh uses `gestures.pull(ui, items)` (`axe drag` with explicit touch moves): on iOS 27.2 `axe swipe` scrolls but never starts a refresh. An edge swipe does not pop a pushed screen there either (`axe swipe`, `axe drag` and the `swipe-from-left-edge` preset all fail on the ride detail and the chat thread), so cases return with `BackButton` and the interactive pop is a device check. A scroll that must stop near a target uses `gestures.drag(ui, start, end)` (a held `axe drag`): there a 40 pt `axe swipe` does not scroll at all and a 300 pt one flings about 385 pt, while a held drag moves its distance less about 10 pt of touch slop (a long one can still carry on by up to about 50 pt).

A SwiftUI `Toggle` row reports the whole row as its frame, but only its switch flips it, and an instant tap on the switch rarely lands on iOS 27.2 (row centre 0 of 20, switch 1 of 12, a 0.2 s touch on the switch 10 of 10), so cases flip a toggle with `UI.flip(identifier)`. The hold gestures use `UI.press(identifier, seconds)` and `UI.press_at(frame, seconds)` in `driver.py` (`axe touch --down --up --delay`; each call costs about 1.2 s of overhead on top of `seconds`). `verification/ui/choose.py` is the bounty selection helper (named `choose.py` because a `select.py` would shadow the standard library module and break every case): `choose`, `hold_select`, `release_early`, `hold_reads`, `selected_args`, `wait_selected`, `assert_none_selected`, `assert_one_selected`, `attempts`, `assert_attempts`, `write_delay_s`, and the video analysis `fill_progress`, `label_split` and `analyse`.
`-uiVerifySignedIn [onboarded]` starts with the fixture session already signed in (with `onboarded`, onboarding is also done, so the app opens on home); `reach_home` then only waits for home. Cases that just need home, tabs or payee use it; only cases that test welcome, sign-in or onboarding go through welcome, and they call `ui.at_rest()` (or `sign_in_apple`) before tapping, because any continuous motion blocks `axe tap`.
`-uiVerifyQr <names>` replaces the screenshot picker and camera at the decode boundary: each pick
returns the next fixture in the comma-separated list (`duitnow`, `paying`, `dynamic`, `alipay`,
`wechat`, `none`), so a case can show an error and then a success. The system photo picker never
opens, so captures taken after an injected pick are named `injected-…` and the case docstring says so.
Without `-uiVerifyQr` the app uses the device source (expo-image-picker + `scanFromURLAsync`):
`payee_qr_real` adds the PNGs in `media/` to the Simulator library with `xcrun simctl addmedia`
before each pick, finds the picker cell by the image's tint (Alipay `#b8e4ff`, DuitNow TNG
`#ffd8a8` light modules) and taps it by coordinates, because the picker runs out of process and
`axe describe-ui` does not expose its cells. simctl cannot remove photos, so each image is added only once per
Simulator: `.verify/qr-media/<udid>` lists the images already added (`verify:clean` removes it, and the next run adds
them once more). The picker lists the oldest first, so the case swipes the grid up (at most 30 times, at rest between
swipes, distances taken from the screen frame) until a cell with the image's tint is in view; it does not depend on order
or count. The PNGs were made with segno
1.6.1 (scale 12, border 8); the DuitNow payload is a static TNG code for NURUL AINA BINTI AHMAD
with a valid CRC. Each run writes
`result.json` with commit, locale, Xcode, device, `videos` (every `.mp4` in the case folder; an empty one fails the run) and `duration_s` (wall-clock seconds of that
case, locale and appearance); the runner ends with a per-case timing table and the total, and
`verify:build` prints its own wall-clock seconds.
`log.txt` starts with the Simulator's name and lists every timed command (AXe calls, screenshots, `simctl appearance` and
`launch`, the case budget) with its duration, `TIMEOUT` on the ones that timed out, and ends with a `latency on <Simulator>`
line (count, median, slowest, timeouts); a timeout message adds the median call time, which separates a slow Simulator from
a stuck screen. A case gets 180 s unless it declares `BUDGET = <seconds>`. The app shows and picks times in the
device zone (234), so the runner launches it with `SIMCTL_CHILD_TZ` set to `Asia/Kuala_Lumpur`, or to the case's
`TIME_ZONE = '<zone>'`, and runs the case script with the same `TZ`, so `datetime.fromtimestamp` in a case reads the
app's clock whatever zone the Mac is in. A case whose outcome depends on the hour of day (quiet hours, 今天 or 明天)
declares `LOCAL_HOURS = [9, 10]` instead: the runner picks, once per run, the fixed-offset zone (`Etc/GMT-5`) that puts
the device at the first of those hours that is not Malaysia's offset, and logs it as `time zone:` in `log.txt`. Two command timeouts in one run, or AXe failing with 「Timed out creating the simulator remote automation session」, mark that
Simulator stalled (`heal.py`; the session error came back on every Simulator 15–30 min after a fresh boot and kept failing until it was shut down, 2026-11-10): the runner prints `STALL`, shuts it down, boots it and reinstalls the app, and retries a
failed run once on another Simulator (the stalled one only when it is the last left; idle Simulators wait for busy ones
so a retry has somewhere to go). The first attempt's log is kept as `stalled-log.txt`, `result.json` records
`stalledDevice` and `retriedOn`, a pass on retry reads `(retried after a stalled device)`, a second stall fails naming
both Simulators, and the final report lists every stall. Three consecutive attempts on one Simulator that fail with the same timeout class (screenshot, `axe <command>`, or the case budget) stop the whole run with a render server CPU sample; a reboot does not reset that count. `python3 -m unittest test_breaker test_heal` in `verification/ui` covers both rules. Only one `verify:ui` run may drive the Simulators at a time; a second run
exits instead of interleaving taps with the first. Every run also takes the machine-wide lock `/tmp/ios-ui-verify.lock` shared with other projects' runners and waits while another project holds it, printing the holder. The lock does not cover `verify:build` or
scripts that drive the Simulator outside the runner. Stopping a run mid-case left every later run on that Simulator `video missing` until it was shut down (`xcrun simctl shutdown <udid>`; the next run boots it). Do not click or scroll in the Simulator window
while a run is in progress: a pointer drag reaches the app as a real touch, and a home case once
failed because a stray drag scrolled 悬赏 back to the top.

`ocr.find(ocr.lines(shot), pattern, within)` reads on-screen text with Vision (`ocr.swift`) for text inside a single
VoiceOver element, such as a board card whose parts have no frames of their own. `ocr.lines_in(shot, locale)` reads a Latin locale twice (zh-Hans first misreads Latin, en-US first loses Chinese), and `board.assert_tier_whole` checks a tier read that way against `textwidth.swift`. Motion that must be timed uses
`recording.clip(ui, name)`: it pauses the run video (`run.mp4`, then `run-2.mp4`, …), records `<name>.mp4` around the
interaction, and `recording.frames(video, dir)` (`frames.swift`) returns each frame with its video timestamp, so the
timing does not depend on screenshot latency. It reads each frame as sRGB: the recording's colour tag is wider than its
values, and converting from the tag moved the dark hold gold #D99A2B to (226, 149, 0) (2026-11-10). Swift helpers compile once to `.verify/<name>` through `swifttool.py`.

Shell and home cases sign in through `reach_home`. `Shot` reads screenshot pixels in points, so
cases assert colours against `src/ui/theme/tokens.ts` (`token`, `assert_colour`), the 悬赏令 halo
(`glow`) and the 小貘 button outline (`assert_tapir_button`).

## Adding a case

1. Add or reuse a scene in `src/debug/scenes.tsx`; it calls `onReady` once settled, which shows
   the `ui-verify-ready` marker.
2. Write `cases/<name>.py`: docstring = behaviour sentence; `DEPS = [...]` path prefixes the case
   depends on (feature folders, routes, helpers such as `verification/ui/payee.py`; shared code and Debug scenes are
   implied, so `DEPS = []` is valid); `SCENE = '<id>'` if it starts from a scene (the runner launches with `-uiVerifyScene <id>`); optional `LOCALES = [...]`; wait on
   identifiers, assert, capture. Cases receive the locale as `ui.locale` for controls that only
   expose a localized label (native toolbar buttons); SwiftUI views from `@expo/ui` take their
   identifier from `testID` or the `accessibilityIdentifier` modifier.
3. Controls a case touches need a `testID`; plain `View`s also need `accessible` to appear in the
   accessibility tree.
4. Run both appearances and open the screenshots before reporting.
5. Reference the case from the acceptance criterion it proves in `docs/story-map.md`; the story-map
   check warns about a case no criterion references.
