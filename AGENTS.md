# Tapiro

- Tapiro is a mutual-help app for Chinese students in Malaysia. iOS only; never Android.
- Stack: Expo SDK 57 (React Native 0.86), TypeScript, Expo Router, bun. Upgrade to SDK 58
  once it is stable. Install packages with `bunx expo install`, not `bun add`.
  Read the versioned Expo docs (`https://docs.expo.dev/versions/v57.0.0/`, index at
  `https://docs.expo.dev/llms.txt`) before writing code; do not rely on memory.
- Backend: Supabase, region `ap-southeast-1` (Singapore). Reason: PostGIS nearest-neighbour
  queries, relational data with RLS, native ID-token auth (docs/research/2026-10-04-feasibility.md).

## Boundaries

- iOS only. Do not add Android implementations, fallback stubs, or Android build scripts.
- Deployment target iOS 26.0 (latest two majors). On SDK 57 set `ios.enableSceneSupport: true`.
  Reason: apps built with the iOS 27 SDK must use the UIScene lifecycle.
- All first-party native code and native UI live in `modules/tapiro-kit`, registered through
  one module facade; no separate bridge packages. Import native APIs only through its typed
  facade; remove event subscriptions on unmount; UIKit work runs on the main queue.
- When RN cannot meet a UI requirement at system quality, implement it in Swift in the kit
  instead of approximating it in RN. Never imitate a control the platform provides, and never
  simulate a native effect (glass, blur, scroll edges) with decorative RN overlays.
- `ios/` is generated by prebuild and never edited by hand; persist changes in app config,
  config plugins, or the kit.
- Dev builds only (`expo run:ios` / EAS). Expo Go cannot run Rive, Google Sign-In, or the kit.
- Never disable code signing (`CODE_SIGNING_ALLOWED=NO`), including Simulator builds.
- Credentials live in Keychain (Supabase session via secure storage). Never commit tokens,
  `.env` files, or private service configuration.
- Auth uses native ID tokens (`expo-apple-authentication`, Google Sign-In) with
  `signInWithIdToken`; no web OAuth. Reason: avoids Apple client-secret rotation.
- Before destructive operations (revert, reset, delete, force-push), inspect the working tree
  and ask for confirmation.

## UI baseline

- Apple HIG is the primary UI requirement. `docs/design-language.md` lists the only places
  Tapiro adds its own expression (stickers, mascot, one accent).
- Preserve native navigation, safe areas, VoiceOver labels on every interactive element, and
  touch targets of at least 44 pt.
- Tabs use Expo Router NativeTabs (`expo-router/unstable-native-tabs`); each tab owns a native
  Stack. Drill-down uses push with system back and interactive pop; sheets are for transient
  flows only.
- Stack headers are transparent and use `scrollEdgeEffects`; do not combine them with
  `headerBlurEffect`. Reason: react-native-screens warns the two effects overlap on iOS 26.
- Dynamic Type: acceptance runs at the default (Large) size. Text keeps the system scaling
  behaviour, but do not add separate layouts or remount logic for accessibility sizes.

## Platform pitfalls

- After adding or removing files under `modules/tapiro-kit/ios`, run `pod install` in `ios/`.
  Reason: CocoaPods snapshots the podspec source glob at install time; new files are not
  compiled until then.
- expo-notifications reports provisional authorization as `undetermined`; check
  `ios.status === PROVISIONAL`. Reason: observed in the feasibility prototype.
- Custom push data goes under the payload's `body` key. Reason: expo-notifications reads
  `content.data` from `userInfo.body`; top-level keys arrive as `data=null`.
- The expo-location plugin adds Always and motion usage strings by default; set them to
  `false` unless a spec requires them. Reason: unused permission strings draw review questions.

## Localization

- Languages: `zh-Hans` (fallback), `en`, `ms`. Resolution: stored in-app choice > system
  locale matched on language + script > `zh-Hans`. Use `expo-localization` plus one i18n library.
- App config declares `supportedLocales`, `CFBundleAllowMixedLocalizations: true`, a `locales`
  map for the app name and permission strings, and `supportsRTL: false`.
- No user-facing string is hard-coded; every string exists in all three locales.

## Animation

- Mascot animation uses Rive (`@rive-app/react-native`, pinned exact version; it is 0.x and
  churns). Load each `.riv` once and share it; commit the generated `*.riv.d.ts`; `riv` is in
  Metro `assetExts`.
- UI motion uses Reanimated, animating transforms and opacity only. Never drive SVG
  attributes via `useAnimatedProps` in lists. Reason: ~3x CPU in the prototype.
- Performance sign-off happens on a device with Instruments, never on Simulator numbers.

## Layout

- `src/app/`: Expo Router routes only; screens compose features.
- `src/features/<feature>/`: one folder per feature; features do not import each other.
- `src/lib/`: Supabase client, i18n, shared utilities. `src/ui/`: design-system components.
- `modules/tapiro-kit/`: the Swift kit. `supabase/`: migrations and Edge Functions.
- `src/debug/`: development-only Debug scenes (fixtures + production components); reachable only
  when `__DEV__` or verify mode. `verification/ui/`: offline UI checks (see its README).

## AI

- Every cloud AI call goes through a Supabase Edge Function pinned to Singapore; no model or
  provider key ships in the app. Reason: keys in a client are extractable.
- Primary model: Qwen on Alibaba Model Studio international (Singapore), per-workspace
  endpoint, pinned model IDs. Fallback: DeepSeek models through the same Model Studio account;
  never the DeepSeek direct API. Reason: data stays outside the PRC and is not used for
  training; direct DeepSeek stores data in the PRC (docs/research/2026-10-04-ai-providers.md).
- Apple on-device Foundation Models is optional, always gated on
  `SystemLanguageModel.default.availability`; Malay always uses the cloud path. Reason: no
  Malay support; unavailable on mainland-China iPhones and pre-iPhone 15 Pro devices.
- The AI never performs an action: tool calls produce drafts, and nothing is published,
  accepted, cancelled or sent to another user without the user's tap.
- Before the first cloud AI call, show a consent screen naming the provider and purpose, and
  record the consent. Reason: App Review 5.1.2(i) and PDPA cross-border transfer.
- A per-user daily limit on AI usage is enforced in the Edge Function.
- Speech-to-text tries SpeechTranscriber → DictationTranscriber → SFSpeechRecognizer on device,
  then cloud Qwen ASR; map en-MY to en-US. Speech is verified on a physical device only.
  Reason: none of the engines produced output on the iOS 26.5 Simulator.
- Native AI and speech live in `modules/tapiro-kit`: map native errors to typed result codes
  in Swift, stream through events tagged with a `requestId`. Reason: thrown Swift errors reach
  JS as untyped `UnexpectedException`.
- Every AI flow has a manual path that works without AI.

## Docs and specs

- Specs: `docs/specs/YYYY-MM-DD-<topic>-design.md`, indexed in `docs/specs/README.md`.
  Plans: `docs/plans/YYYY-MM-DD-<topic>.md`. These locations override any tool default
  (for example superpowers' `docs/superpowers/specs`).
- New specs start from `docs/specs/_template.md` with `status: proposed`. Only the human
  moves a spec to `approved`.
- After a feature is implemented and before its PR is opened or updated, run the
  `spec-lifecycle` skill to append the Implementation Record, set `status: implemented`,
  and update the index. `node scripts/check-specs.mjs --dir docs/specs` must pass.
- An overturned design gets a new spec that supersedes the old one; never delete a spec.

## Checks

- Before commit: `bunx expo lint <files>`, `bunx tsc --noEmit`, `bun run format:check` (the same
  command CI runs; run it after any scripted edit to JSON or config).
- Logic tests run with `bun test`. UI work runs `node scripts/design-check.mjs`; tokens live only in
  `docs/design-language.md` and `src/ui/theme/tokens.ts`, and product code never uses raw colours,
  font sizes or font families.
- Tests when behavior changes; a production bundle when the build can change. Prefer
  behavioural checks over implementation snapshots.
- UI changes add or update a check under `verification/ui` (`bun run verify:build`,
  `bun run verify:ui`) and run it in light and dark; screenshots for state, video for motion.
  Missing scenes, missing identifiers and timeouts fail; open the screenshots before reporting.
- UI checks run in `zh-Hans`. A case that shows long copy also declares `LOCALES` with `ms` to
  catch truncation. Light and dark are always both covered.
- Verify builds share one DerivedData per checkout (`.verify/DerivedData`). Never pass a
  per-task `-derivedDataPath`, copy the checkout to a temp directory, or call `simctl create`
  directly; the runner owns the `Tapiro Verify` Simulator. Reason: the disk incident below.
- Verify mode (`EXPO_PUBLIC_UI_VERIFY=1`) replaces services at their boundary only; it never ships
  enabled.
- Report skipped checks and why.

## Conventions

- Conventional Commits with scope: `feat(bounty): ...`, `fix(auth): ...`.
- Components under 300 lines, files under 500 lines. No comments unless they explain
  unexpected behaviour or a hidden constraint.

## Rules from incidents

- Keep at least 15 GB free disk before iOS Release builds. Reason: parallel prototype
  builds filled the disk and the working directory was lost (2026-10-04).
- CI caches CocoaPods. Reason: Rive's `pod install` downloads a 122 MB xcframework and
  failed once with a TLS error.
- Keep `eslint` on major 9. Reason: `eslint-plugin-react` (via `eslint-config-expo`) does not
  support ESLint 10; `expo lint` crashed with `contextOrFilename.getFilename is not a function`.
- `tsconfig.json` lists global type packages in `types` (currently `bun`). Reason: TypeScript 6
  no longer loads `@types/*` automatically; `bun:test` failed to resolve until it was listed.
- UI cases start scenes with the launch argument `-uiVerifyScene <id>`, never `simctl openurl`.
  Reason: custom-scheme deep links raise the system "Open in Tapiro?" prompt and block the run.
- Keep the root `ThemeProvider` in `src/app/_layout.tsx`, and every case asserts appearance with
  pixels. Reason: removing it left the navigation bar white in dark mode while all AX
  assertions passed; only a screenshot showed it.
